남은 확인: 서버 지역을 DB(Neon, 싱가포르) 옆인 `sin1`로 옮겼다(2026-11-21, `vercel.json`의 `regions`). 그 전에는 서버가 미국 동부(iad1)라 DB에 물을 때마다 태평양을 오갔고, 사용자가 모든 조작이 느리다고 했다. 옮긴 뒤 사용자가 "속도 괜찮은 것 같다"고 했다(2026-11-21). 다시 느려지면 누르면 바로 보이는 "불러오는 중" 표시(`loading.tsx`가 하나도 없다)와 요청마다 도는 DB 조회(로그인 확인·허용 확인·옮기기 확인) 줄이기를 새 계획으로 한다. 5-4 옮기기는 실서비스에서 끝났다(2026-11-21, PR #43·#44 뒤 다시 옮기기). 옛 기록 37개가 같은 기록 12개를 빼고 학력 1·교육 1·자격 3·공백 2·경력 1·프로젝트 7·활동 2·사례 17로 옮겨졌다. 성과 사례(STAR) 5개는 경력 아래 사례로, AI ERP 기록 4개는 프로젝트 하나로 모였다. 확인됐던 성과 사례는 확인된 사례로 이어졌지만, 경력이 미확인이라 경력에 `맞음`을 눌러야 쓰인다. 관리 화면 프롬프트 점검(호출 20번)으로 새 가져오기(이제 답 모양을 지시로 받는다)·정리·사례 정리·사례 판정·옮기기 예시가 실제 AI에서 통과하는지 본다. 경험 기록 화면의 `가져오기`로 글 하나를 넣어 새 가져오기가 되는지도 본다. 지원 공고 하나에서 `다시 보기`로 채점이 학력·자격을 근거로 쓰는지, 옛 기록으로 만든 자소서·이력서에 "기록 구조가 바뀌어 다시 만들어야 합니다"가 보이는지 본다. 5-3은 실제 지원한 공고 하나에서 `제출함`을 눌러 제출본 화면의 이력서·자소서가 낸 것과 같은지 본다. 5-2는 실제 AI로 확인했다(2026-11-19). 공통본 줄에 기록에 없는 내용이 없었고, 맞춤본 강조는 학력을 요건 충족만으로 고르던 것을 고쳤다(PR #29). 자소서 고르기와 맞춤본 강조가 비던 원인은 AI가 경험 별명(E1) 대신 경험 이름을 적어 보낸 것이었고, 이름도 받아들이고 지시문을 고쳤다(PR #30~#32). 프롬프트 점검은 84/84 통과(2026-11-19). 점검 결과에 'AI가 보낸 답(진단용)' 줄이 있어, 실패하면 그 줄로 AI의 원래 답을 본다. 5-1은 실제로 지원한 공고 하나에 문항을 넣어 답에 기록에 없는 내용이 없는지 아직 보지 않았다. DB 연결 재시도(PR #23)는 실제로 Neon이 깨어나는 상황을 아직 겪지 않았다. 5분 넘게 쉬었다가 첫 요청이 들어온 뒤 Vercel 기록의 "DB 연결을 다시 시도합니다" 경고와 Neon의 `start_compute` 시각을 맞춰 보고, 세션 조회 실패가 없는지 본다(Vercel 기록은 1시간만 남는다). 4-2는 실제 공고로 한 번 확인했고(2026-11-18), 담당 업무를 우대로 낮추고 입사 가능 시기 같은 조건을 빼도록 고쳤다(PR #21): 같은 공고에서 `다시 보기`로 다시 확인한다. 사람인 말고 다른 채용 사이트의 주소 읽기는 사용자가 써 보다 안 되는 곳을 알려 주면 고친다. 빌드에 `pg`의 `sslmode` 경고가 나온다: `pg` 9로 올릴 때 Vercel의 DB 주소를 `sslmode=verify-full`로 바꾼다(사용자가 직접).
