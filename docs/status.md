| 5-5 | 공고 서류와 자유양식: 공고를 읽을 때 제출 서류·자소서 문항을 함께 뽑고(원문에 없는 문항은 버림), 공고 화면에서 서류를 고르고 `다시 읽기`, 지원하면 찾은 문항을 채운다. 문항이 없으면 자유양식 항목을 체크해 넣는다. 문항마다 유형(경험형·동기포부형·자기소개형)을 두고 고르기 AI가 정한다. 동기·포부·성장과정 같은 재료는 AI가 공고와 내 확인된 기록(사례·학력·교육·자격)을 맞대 연결고리마다 고를 수 있는 질문으로 묻고, 고른 답만 근거로 쓴다("내 답: 주제"). 지난 답은 같은 주제 질문의 선택지 하나로 붙는다(지원동기·포부는 같은 회사만). 답이 필요한 문항에 답이 없으면 쓰지 않는다(`docs/superpowers/plans/2026-11-21-05e-documents-freeform.md`, PR #47·#48·PR 3) |
| 5-6 | 회사 조사: 공고를 `지원`으로 정하면 Claude 웹 검색(한 조사에 검색 5번까지)으로 회사의 인재상(홈페이지 도메인 안)과 최근 소식을 출처와 함께 찾아 공고 화면에 보인다. 이번 검색 결과에 없는 주소·홈페이지 밖의 인재상은 코드가 버린다. 사용자가 인재상에 `맞음`, 소식에 체크한 것만 지원동기 묻기와 동기포부형 문항 쓰기·고치기에 쓴다(새 표 `postings_research`, 사용자·회사 단위). 회사 정보가 근거인 문단은 "회사 정보: 출처 호스트"로 보이고 제출본에도 그렇게 얼린다. 회사 정보의 숫자는 그 정보를 단 문단에서만 허용하고, 회사 정보만 근거인 문단은 근거 없음, 체크를 풀거나 다시 조사한 회사 정보는 바뀜으로 표시한다(`docs/superpowers/plans/2026-11-24-05f-company-research.md`, PR #52·PR 2) |
| 5-7 | 경력기술서: 확인된 경력마다 회사 머리(회사·부서·직급·기간·담당 업무)는 코드가, 그 아래 업무(사례)·딸린 프로젝트마다 한 일·성과 줄은 AI가 확인된 기록으로 쓴다(새 표 `applications_careers`, 목적 `career_write`·`career_emphasis`). 트랙마다 공통본, 지원 공고마다 맞춤본(AI가 강조할 항목을 이유와 함께 고르고 체크한 것만 회사 맨 위로 올려 다시 씀). 줄 고치기·옮기기·빼기·다시 쓰기, 금지 표현·그 항목 기록에 없는 숫자·바뀐 기록·쓸 수 없는 항목·빠진 항목 표시. 공고 서류에 경력기술서가 있으면 제출본에 얼린다. 확인된 경력이 없으면 "경력이 없어 경력기술서를 만들 수 없습니다"(`docs/superpowers/plans/2026-11-24-05g-career-statement.md`, PR #55·PR 2) |
| 이력 묶어 보기 | 경험 기록을 `기본정보 · 이력 · 경험 사례`로 바꿨다. `이력`은 경력·학력·교육 기관·대내외활동·개인·자격·어학·수상 순서로 묶고 기관 아래에 프로젝트를 들여 보이며, 오른쪽(휴대폰은 위쪽)에 목차를 둔다. `경험 사례`도 같은 순서로 기관 → 프로젝트 → 사례로 묶는다. 대내외활동 아래 프로젝트, 학교·교육 과정 아래 사례를 둘 수 있고(칸 3개 추가), 그 사례는 자소서·채점 근거로 쓰인다(이력서는 그대로). 새 연결이 있으면 다시 옮기기를 막는다(`docs/superpowers/plans/2026-11-25-record-tree.md`, PR #57) |
