**다음 할 일: 경험 기록 개편을 설계한다(설계 6.3을 바꾸므로 brainstorming으로 사용자와 정한다).** 사용자가 자소서를 마음에 들어 하지 않는다(2026-11-20). 지금은 모든 구분(재직·프로젝트·교육·학력·자격·공백·기타)이 같은 칸(상황·한 일·결과·수치)과 같은 루브릭을 쓰고, 재직 하나가 기록 하나라 자소서에 쓸 장면을 꺼내기 어렵고, 지원 동기·입사 후 포부·자기소개에 쓸 재료(왜 이 회사·직무인가, 목표, 가치관·일하는 방식)를 적을 자리가 없다. 논의한 방향: (1) 이력 사실(학력·자격·수상·경력 머리: 짧은 칸, 단순한 검증, 이력서용)과 (2) 경험 장면(경력·프로젝트 아래 여러 개, 상황·판단·한 일·결과·배운 점, 자소서용)을 나누고, (3) 동기·목표·가치관 기록을 두고, (4) 자소서 문항을 유형(경험형·동기포부형·자기소개형)으로 나눠 다른 재료를 쓴다. 학력·자격을 자소서 후보에서 빼는 작은 수정은 먼저 배포했다.

남은 확인: 5-3은 실제 지원한 공고 하나에서 `제출함`을 눌러 제출본 화면의 이력서·자소서가 낸 것과 같은지 본다. 5-2는 실제 AI로 확인했다(2026-11-19). 공통본 줄에 기록에 없는 내용이 없었고, 맞춤본 강조는 학력을 요건 충족만으로 고르던 것을 고쳤다(PR #29). 자소서 고르기와 맞춤본 강조가 비던 원인은 AI가 경험 별명(E1) 대신 경험 이름을 적어 보낸 것이었고, 이름도 받아들이고 지시문을 고쳤다(PR #30~#32). 프롬프트 점검은 84/84 통과(2026-11-19). 점검 결과에 'AI가 보낸 답(진단용)' 줄이 있어, 실패하면 그 줄로 AI의 원래 답을 본다. 5-1은 실제로 지원한 공고 하나에 문항을 넣어 답에 기록에 없는 내용이 없는지 아직 보지 않았다. DB 연결 재시도(PR #23)는 실제로 Neon이 깨어나는 상황을 아직 겪지 않았다. 5분 넘게 쉬었다가 첫 요청이 들어온 뒤 Vercel 기록의 "DB 연결을 다시 시도합니다" 경고와 Neon의 `start_compute` 시각을 맞춰 보고, 세션 조회 실패가 없는지 본다(Vercel 기록은 1시간만 남는다). 4-2는 실제 공고로 한 번 확인했고(2026-11-18), 담당 업무를 우대로 낮추고 입사 가능 시기 같은 조건을 빼도록 고쳤다(PR #21): 같은 공고에서 `다시 보기`로 다시 확인한다. 사람인 말고 다른 채용 사이트의 주소 읽기는 사용자가 써 보다 안 되는 곳을 알려 주면 고친다. 빌드에 `pg`의 `sslmode` 경고가 나온다: `pg` 9로 올릴 때 Vercel의 DB 주소를 `sslmode=verify-full`로 바꾼다(사용자가 직접).
