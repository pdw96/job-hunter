# 이력 묶어 보기 설계

2026-11-25 승인. 5-4(경험 기록 개편, `2026-11-20-records-and-documents-design.md`)의 메뉴와 연결을 고친다.

## 왜

옮기기(5-4)가 끝난 뒤 사용자가 "경력 및 프로젝트 연결이 내 경험과 다르다"고 했다. 프로젝트를 경력·학교·교육 과정에 딸리게 하는 연결은 이미 있지만 화면에 보이지 않는다(경력 탭에는 경력만, 경험 사례 탭에는 경력·프로젝트·활동이 나란히). 그래서 무엇이 어디에 딸렸는지 모르고, 틀린 연결을 찾아 고칠 수 없다. 또 학교·교육 과정에서 겪은 일은 사례로 붙일 곳이 없다.

사용자가 원하는 것(2026-11-25): 내 이력이 실제 순서대로 보이고, 서류에도 소속이 드러난다. 모양은 대분류(기관) → 중분류(프로젝트) → 상세(사례).

## 목표

- 경험 기록의 메뉴를 `기본정보 · 이력 · 경험 사례`로 한다. 지금의 `학력`·`경력`·`자격·어학·수상` 탭은 `이력` 하나가 된다
- `이력` 탭은 대분류 여섯 묶음을 이 순서로 보인다: 경력, 학력, 교육 기관, 대내외활동, 개인, 자격·어학·수상. 기관마다 그 아래 프로젝트를 들여 보인다. 자격·어학·수상은 아래가 없는 한 줄 기록이라 들여쓰기 없이 취득 월 최근 순으로 둔다
- 대분류 목차를 오른쪽에 세로로 둔다. 누르면 그 묶음으로 내려가고, 스크롤해도 따라오며 지금 보는 묶음을 표시한다. 화면이 좁으면(휴대폰) 목차를 위쪽 가로줄로 보인다
- `경험 사례` 탭은 지금 모양(묶음마다 사례 목록, `+ 사례 추가`)을 두되, 묶는 순서를 이력과 같게 한다: 기관 → 그 아래 사례와 프로젝트 → 프로젝트 아래 사례
- 새 연결 두 가지: 대내외활동 아래 프로젝트, 학교·교육 과정 아래 사례
- 학교·교육 과정 아래 사례도 다른 사례처럼 자소서 근거와 채점 근거로 쓰이고, 소속 이름이 함께 간다

## 하지 않는 것

- 중분류 종류를 늘리지 않는다. 중분류는 프로젝트 하나다. 프로젝트가 아닌 일(회사 업무 등)은 사례를 기관 바로 아래에 둔다
- 이력서 모양을 바꾸지 않는다. 프로젝트는 지금처럼 프로젝트 칸에 두고 이름 옆에 소속을 보인다(소속이 확인됐을 때). 학력·교육 칸은 코드가 쓴 학위·학점·과정 줄만 둔다. 학교·교육 과정 아래 사례를 이력서에 넣지 않는다
- 경력기술서는 그대로다(경력 아래 사례·프로젝트)
- 가져오기(노션·글)는 그대로다. 가져온 뒤 프로젝트·사례의 `소속`을 화면에서 바꾸면 된다
- 기록을 다시 옮기거나 지금 연결을 AI가 고치지 않는다. 사용자가 묶어 보기 화면에서 보고 `소속`으로 고친다
- 표를 합치지 않는다(아래 방법 B)

## 피해야 할 것

- 지금 기록·이력서·경력기술서·자소서·제출본이 하나라도 달라지거나 깨지는 것. 이번 변경은 칸을 더할 뿐 지금 행을 바꾸지 않는다
- 이력 탭에서는 회사 아래, 사례 탭에서는 나란히처럼 두 탭의 묶음이 다른 것(처음 문제가 남는다)

## 방법

| 방법 | 내용 | 결과 |
|---|---|---|
| A. 지금 표에 연결 칸만 더하기 | `experiences_projects.activity_id`, `experiences_scenes.education_id`·`course_id`를 더하고 검사 제약을 넓힌다. 화면은 두 탭을 묶음으로 다시 그린다 | **택함**(사용자 2026-11-25). 지금 자료와 서류 코드가 그대로 돈다 |
| B. 경력·학교·교육 과정·활동을 '기관' 표 하나로 | 묶음은 깔끔하다 | 5-4의 표·서류 코드를 거의 다시 짜고 운영 자료를 다시 옮겨야 해서 버림 |
| C. DB는 두고 화면만 묶기 | 가장 작다 | 학교·교육 과정 아래 사례를 둘 수 없어 버림 |

## 정한 것

### 연결 규칙

- 프로젝트의 소속: 경력·학교·교육 과정·대내외활동 중 하나, 또는 없음(개인). 하나까지
- 사례의 소속(머리): 경력·학교·교육 과정·대내외활동·프로젝트 중 정확히 하나
- 학교·교육 과정 아래 사례도 다른 사례처럼 머리가 확인됨이어야 지원서에 쓴다(5-4 「결정」과 같다). 학교·교육 과정은 이력 사실이라 `맞음` 한 번으로 확인한다
- 사례가 딸린 학교·교육 과정은 지우지 않는다(경력·프로젝트·활동과 같은 규칙)

### 이력 탭

```
[기본정보] [이력] [경험 사례]

경력                                         ┌ 목차(오른쪽, 따라옴) ┐
 ○○커머스  사원  2023.01~2024.12        확인됨
   └ 프로젝트  물류 대시보드  2024.03~08
 공백  2025.01~2025.06
 + 경력 추가   + 공백 추가
학력
 ○○대학교 컴퓨터공학 학사
   └ 프로젝트  졸업 작품
 + 학교 추가
교육 기관
 △△ 부트캠프
   └ 프로젝트  팀 쇼핑몰
 + 교육 과정 추가
대내외활동
 □□ 동아리
 + 활동 추가
개인
 프로젝트  개인 블로그
 + 프로젝트 추가
자격·어학·수상
 정보처리기사  자격  2023.06
 TOEIC 850     어학  2024.01
 + 자격·어학·수상 추가
```

- 대분류 안은 지금처럼 시작 월 최근 순이다. 경력 묶음은 공백을 날짜 순으로 섞는다(지금과 같다)
- 기관을 누르면 지금의 그 기록 화면, 프로젝트를 누르면 프로젝트 화면으로 간다. 소속은 프로젝트 화면의 `소속` 칸에서 바꾼다(소속 후보에 대내외활동이 더해진다)
- 이력 탭에서는 사례를 보이지 않는다. 사례 수만 기관·프로젝트 옆에 적는다(예: `사례 3개`)
- 지금 경력 탭의 주장 확인(가져온 경력의 열린 주장)은 이력 탭의 경력 묶음에 그대로 둔다
- 옛 주소(`/records?tab=school`, `?tab=job`, `?tab=credential`)는 이력 탭(그 대분류 자리)으로 보낸다
- 목차를 둘 자리: 지금 본문 폭(`max-w-3xl`) 안에 넣을지, 경험 기록 화면만 넓은 화면에서 폭을 늘릴지는 빌더가 정한다

### 경험 사례 탭

```
○○커머스 · 경력                 사례 2개   확인됨
  • 재고 맞추기 업무
  └ 물류 대시보드 · 프로젝트      사례 1개
      • 배송 지연 원인 찾기
      + 사례 추가
  + 사례 추가
○○대학교 · 학력                 사례 0개
  └ 졸업 작품 · 프로젝트          사례 2개
      • …
△△ 부트캠프 · 교육 기관 …
□□ 동아리 · 대내외활동 …
개인 프로젝트
  개인 블로그 · 프로젝트 …
```

- 묶음 순서는 이력 탭의 대분류 순서와 같다(자격·어학·수상은 사례가 없어 빠진다). 같은 모양의 오른쪽 목차를 둔다(설계자의 판단: 두 탭이 같은 모양이어야 덜 헷갈린다)
- 묶음마다 지금처럼 머리 확인 표시, 미확인이면 `맞음`, `+ 사례 추가`(AI 인터뷰 / 직접 쓰기)를 둔다
- 사례 화면의 `소속` 후보에 학교·교육 과정이 더해진다

### 서류에 가는 소속

- 학교 아래 사례: 소속은 학교 이름(전공이 있으면 "학교 · 전공")
- 교육 과정 아래 사례: 소속은 "과정 이름 · 교육 기관"
- 대내외활동 아래 프로젝트: 이력서 프로젝트 이름 옆 소속은 활동 이름
- 소속 이름은 그 소속이 확인됐을 때만 쓴다(지금 프로젝트 규칙과 같다). 소속이 바뀌면 그 소속을 쓴 서류 항목은 "바뀐 기록"으로 표시된다(지금 규칙과 같다)
- AI 인터뷰·사례 판정에 보내는 머리 칸: 학교는 학교·전공·학위, 교육 과정은 과정·기관. 연락처와 학교 소재지는 보내지 않는다

### 검토에서 정한 것(설계자의 판단, 2026-11-25)

- 다시 옮기기(`resetMoves`)를 막는 검사(`resetBlock`)에 새 연결 두 가지를 더한다: 직접 만든 사례가 옮겨 온 학교·교육 과정에 딸렸거나, 직접 만든 프로젝트가 옮겨 온 활동에 딸렸으면 막는다. 막지 않으면 외래 키 오류로 서버가 실패하거나, 사용자가 고친 연결이 말없이 풀린다. `move*` 코드는 이 검사만 고친다
- 트랙 범위는 다른 사례와 같이 머리(학교·교육 과정)와 사례 중 좁은 쪽을 쓴다(`narrowerScope`)
- 학교·교육 과정 아래 사례의 원천 종류(`kind`)를 `school`·`training`으로 두지 않는다. 자소서 고르기(`select.ts`)가 `school`을 걸러 내서 사례가 빠진다. 사례 원천에 맞는 종류를 빌더가 고른다
- 학교·교육 과정을 사례의 머리 목록에 넣어도 이력서 원천(`listRecordResumeSources`)의 머리 항목에는 넣지 않는다. 이력서에는 지금처럼 코드 줄로만 간다
- 학교·교육 과정에는 '진행 중' 칸이 없다. 사례 기간이 비어 그 기간을 빌릴 때, 재학 중이거나 끝 월이 없는 학교가 기간 검사에서 미충족이 되지 않게 빌더가 정한다

## 빌더에게 맡기는 것

- 마이그레이션의 칸 이름, 외래 키의 삭제 동작(지금 사례·프로젝트의 소속 칸과 맞춘다), 검사 제약 이름
- 묶어 보기의 컴포넌트 나누기, 접기·펼치기를 둘지, 휴대폰 폭에서의 들여쓰기
- 옛 기록 옮기기 코드(`move*`)는 손대지 않는다. 다음 계획(옛 표 지우기)에서 걷어 낸다. 다만 타입을 넓혀 컴파일이 깨지면 그 자리에서만 맞춘다
