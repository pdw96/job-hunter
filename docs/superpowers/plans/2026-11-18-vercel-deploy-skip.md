# Vercel 배포 줄이기

**목표:** 앱과 상관없는 변경으로 Vercel 배포가 만들어지지 않게 한다.

**왜:** 2026-11-18에 계정 전체 하루 배포 한도(무료 100회)에 걸렸다. 11-17 15:49 ~ 11-18 09:19의 100회 가운데 job-hunter가 56회였고, 대부분이 작업 브랜치(`claude/*`)에 푸시할 때 생긴 미리보기였다. 화면 확인은 로컬 미리보기로 하므로 Vercel 미리보기는 쓰지 않는다. 사용자가 결제해 한도는 풀렸지만, 쓸데없는 빌드를 줄인다.

## 정한 것

- 「결정」(2026-11-18, 사용자) 둘 다 한다
  - `vercel.json`의 `git.deploymentEnabled`로 `claude/*` 브랜치는 배포하지 않는다
  - `ignoreCommand`(`scripts/vercel-ignore.mjs`): 이 브랜치의 지난 성공 배포(`VERCEL_GIT_PREVIOUS_SHA`) 뒤 바뀐 파일이 문서(`docs/`, `*.md`), `.claude/`, `.github/`, 테스트(`*.test.ts|tsx|mjs`)뿐이면 빌드를 건너뛴다. 지난 배포가 없거나 바뀐 파일을 알 수 없으면 빌드한다
- 건너뛴 배포도 Vercel에 "취소됨"으로 남는다
- 마이그레이션(`drizzle/`), `package.json`, 설정, 앱 코드가 하나라도 바뀌면 빌드한다(실제 서비스 마이그레이션은 빌드에서만 적용되므로)

## 확인

- `scripts/vercel-ignore.test.mjs`(판단 함수), 작업 트리를 따로 만들어 실제 커밋으로 돌려 봄: 문서만 바뀐 범위 → 건너뜀(0), 앱이 바뀐 범위 → 빌드(1), 없는 커밋 → 빌드(1), 지난 배포 없음 → 빌드(1)
- 합친 뒤: `main`의 이 변경은 `vercel.json`과 스크립트가 바뀌므로 빌드된다. 그 뒤 문서만 합치는 PR에서 실제 서비스 배포가 "취소됨"으로 남는지, 작업 브랜치 푸시에 미리보기가 생기지 않는지 본다

## 구현하면서 달라진 점
- (검토) 앱 파일을 `docs/`로 옮기면 git이 이름 바꾸기로 보고 옮긴 경로만 보여 빌드를 건너뛰었다. `git diff --no-renames`로 옮기기 전 경로도 센다(임시 git 저장소로 테스트)
