# Job Hunter 3-4번 계획: 노션 내보내기 묶음(zip) 가져오기 Implementation Plan

**Goal:** 노션에서 내보낸 zip을 그대로 올리면, 경험별로 본문과 하위 페이지를 한 묶음으로 모아 묶음마다 가져온다. 노션에 정리해 둔 금지 표현과 증빙 메모는 해당 칸에 들어간다. 같은 내용을 여러 번 묻지 않게 주장을 줄인다.

**배경:** 사용자의 자료는 노션 데이터베이스다(2026-11-17 확인). 내보내면 파일 68개(페이지 66개, 요약 표 2개), 약 10만 자가 나온다. 경험 하나가 "본문 페이지 + 하위 페이지 여러 개"(증빙·확인 상세, 사용 금지 표현, 성과 사례 등)로 나뉘어 있다. 지금의 가져오기는 글 하나(4만 자까지)만 받아서 이 자료를 넣을 수 없다. 또 실제 AI 점검에서 같은 수치를 서너 번 묻는 것이 보였다.

**Architecture:** zip은 **브라우저에서 푼다**. 서버에는 사용자가 고른 묶음의 글만, 지금 있는 붙여 넣기 경로(`importAction`)로 하나씩 보낸다. 그래서 서버에 새 저장소나 새 호출 경로가 생기지 않는다. 파일 목록을 묶음으로 나누는 규칙은 순수 함수(`notion-export.ts`)로 두고 테스트한다.

**Spec:** 설계 6.3의 "쌓는 방법"과 "가져온 자료는 주장으로 다룬다"

## Global Constraints

- 앞 계획들의 Global Constraints, `docs/conventions.md`의 규칙을 모두 따른다
- zip과 그 안의 파일은 서버로 보내지 않고 저장하지도 않는다. 고른 묶음의 글만 보낸다
- 노션에 "확인됨"이라고 적혀 있어도 기록은 미확인으로 저장하고 주장을 묻는다(노션 자료도 AI가 쓴 것이기 때문)
- AI 호출은 묶음 하나에 한 번이다. 21묶음이면 21번이고, 월 한도에 걸리면 거기서 멈추고 알린다
- PR은 구현이 끝나면 초안을 풀고, Codex 검토 결과를 확인한 뒤 사용자에게 합칠지 묻는다
- 화면은 `npm run preview:local`로 확인하고 사진을 사용자에게 보낸다. 사용자의 실제 zip은 이 세션 안에서만 쓰고 저장소에 넣지 않는다

## 묶음 규칙

노션 내보내기의 모양:

```
이력 타임라인 8c9d….csv                      ← 요약 표 (쓰지 않는다. 같은 내용이 각 페이지 머리에 있다)
이력 타임라인/
  생산관리 전담 (2023 04~2024 10) 4154….md    ← 본문 페이지
  생산관리 전담 (2023 04~2024 10)/            ← 같은 이름의 폴더
    사용 금지 표현 4154….md                   ← 하위 페이지
    성과 사례 · APHA … 4154….md
```

- 가장 얕은 곳에 있는 `.md`가 본문 페이지이고, 하나가 묶음 하나다
- 본문 파일 이름에서 끝의 ID(32자리)와 `.md`를 뗀 것과 이름이 같은 폴더 안의 `.md`가 모두 그 묶음의 하위 페이지다(더 깊은 폴더 포함)
- 묶음의 제목은 본문 첫 줄의 `# 제목`이다(파일 이름은 노션이 잘라서 쓸 수 없다)
- 묶음의 글 = 본문 + 하위 페이지들. 하위 페이지 앞에 `## [하위 페이지] 제목`을 붙인다. 하위 페이지로 가는 링크 줄(`[제목](…​.md)`)은 지운다
- `.md`가 아닌 파일(그림, 표)은 쓰지 않는다
- zip 안에 zip이 하나 더 있으면(노션이 큰 내보내기를 그렇게 준다) 한 단계까지 푼다
- 묶음의 글이 4만 자를 넘으면 그 묶음은 고를 수 없고, 나눠서 붙여 넣으라고 알린다
- 한도: zip 20MB, 페이지 500개

## 주장을 줄이는 규칙

같은 내용을 한 번만 묻는다.

- 같은 문장이 수치 주장과 역할 주장 둘 다이면 하나로 합친다. 수치 주장으로 묻되, "과장임" 답도 고를 수 있게 한다
- 본문 문장의 숫자가 모두 수치 칸의 어느 줄에 이미 있으면, 그 문장은 따로 묻지 않는다(수치 줄 하나로 묻는다)
- AI가 짚은 구절이 코드가 잡은 역할 주장의 일부이면 넣지 않는다

## Tasks

### Task 1: 묶음 나누기 (순수 함수)
- `src/modules/experiences/notion-export.ts`: `groupPages(files: { path: string; text: string }[])` → `{ title, text, chars, pages, tooLong }[]`
- 테스트: 본문과 하위 페이지 묶기, 잘린 폴더 이름, 깊은 하위 폴더, 링크 줄 지우기, 제목 없는 페이지, csv·그림 무시, 4만 자 초과 표시

### Task 2: 브라우저에서 zip 풀기
- `jszip`을 직접 의존성으로 넣고(이미 `mammoth`를 따라 설치되어 있다) 가져오기 화면에서만 불러온다
- `src/app/(app)/experiences/import/read-zip.ts`: 파일 → `{ path, text }[]`. 안쪽 zip 한 단계, 한도 확인

### Task 3: 화면
- 가져오기 화면의 파일 선택이 `.zip`도 받는다
- zip을 고르면 묶음 목록이 나온다: 제목, 페이지 수, 글자 수, 체크 상자(기본 모두 선택), `전체 선택/해제`
- `가져오기`를 누르면 고른 묶음을 하나씩 보낸다. `3 / 21 가져오는 중`과 `멈추기`를 보여 준다
- 끝나면 묶음별 결과를 보여 준다: 만든 기록, 실패한 묶음과 이유. 한도를 넘으면 남은 묶음은 보내지 않는다
- 실패한 묶음만 다시 보낼 수 있다

### Task 4: 프롬프트와 금지 표현
- `IMPORT_SYSTEM`에 더한다: 원본이 "쓰지 말라"고 한 수치와 표현은 기록에 넣지 않는다 / 원본에 금지 표현 목록이 있으면 `bannedPhrases`에 그대로 옮긴다 / 하위 페이지의 성과 사례는 그 경험의 내용으로 넣되, 뚜렷이 다른 프로젝트일 때만 따로 나눈다
- 코드 검사: `bannedPhrases`는 원본 글에 글자 그대로 있는 것만 받고 30개까지만 둔다
- 프롬프트 점검에 노션 모양의 예시 1건을 더한다(금지 표현이 옮겨지는지, 제외하라는 수치가 빠지는지)

### Task 5: 주장 줄이기
- `claims.ts`의 `findClaims`, `mergeClaims`에 위 규칙을 넣고 테스트한다
- 수치 주장에 `phrase`가 있으면 확인 화면에 "과장임" 버튼을 보여 준다

### Task 6: 확인
- `npm test`, `npx tsc --noEmit`, `npm run lint`, `npm run build`
- 로컬 미리보기에서 사용자의 실제 zip으로 묶음 목록이 맞게 나오는지 확인하고 사진을 보낸다(로컬 미리보기의 AI는 가짜라서 가져온 내용 자체는 실제 서비스에서 확인한다)
- 합친 뒤 사용자가 실제 서비스에서 zip을 올려 본다

## 하지 않는 것

- 노션에 직접 연결해 읽어 오기(계정 연결이 필요하다. 내보내기 파일로 충분하다)
- 노션의 "검증 상태"를 믿고 확인을 건너뛰기
- 요약 표(csv)의 열을 칸에 자동으로 맞추기(노션 표의 열 이름은 사람마다 다르다. AI가 본문 머리의 같은 내용을 읽는다)

## 구현하면서 달라진 점

- 본문 페이지를 "가장 얕은 곳의 `.md`"로 정하지 않고, 얕은 것부터 차례로 보며 아직 어느 묶음에도 들지 않은 페이지를 본문으로 삼는다. 폴더 깊이가 섞인 내보내기도 빠지는 페이지가 없다.
- AI가 짚은 구절은 "코드가 같은 낱말로 묻는 문장의 일부"일 때만 뺀다. 같은 문장 안이라도 다른 표현(예: 주도 문장 안의 "핵심 역할")은 따로 묻는다.
- 한도에 닿았을 때 남은 묶음을 보내지 않도록 `importAction`의 실패 결과에 `stop`을 더했다.
- 로컬 미리보기의 가짜 AI는 `# 제목`으로 시작하는 글을 기록 하나로 만든다.
