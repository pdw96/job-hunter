# 판단표

AI가 멈추고 물을지, 혼자 진행할지를 정하는 표다. 점수는 정답이 아니라 판단을 돕는 표다. 판단표를 느슨하게(덜 묻게) 고치는 것은 사용자 승인을 받는다. 설계: `docs/superpowers/specs/2026-11-17-ai-native-workflow-design.md`

마지막 점검: 2026-11-17 (처음 만듦)

점수: 기준마다 0(낮음), 1(중간), 2(높음). 높을수록 조심하는 쪽이다.

## ① Codex 재검토

지적을 고친 뒤 `@codex review`로 다시 받을지 정한다.

반드시 묻기: 같은 지적이 되풀이된다. 고치려면 설계를 바꿔야 한다. Codex의 지적이 틀렸다고 보여 반박하려 한다.

| 기준 | 2 | 0 | 왜 |
|---|---|---|---|
| 지난 지적의 심각도 | 보안, 데이터 손실, 서버 멈춤 | 문구, 사소한 경우 | 심각한 곳 근처에 결함이 더 있기 쉽다 |
| 고치며 새로 쓴 코드 | 많음 | 몇 줄 | 새 코드에 새 결함이 생긴다 |
| 줄어드는 추세 | 지적 수가 그대로, 영역이 넓어짐 | 줄고 같은 곳만 다듬음 | 수렴하는지 본다 |
| 영역의 위험도 | 외부 입력, 주소 열기, 로그인, AI에 보내는 자료 | 화면, 문서 | 놓치면 피해가 크다 |
| 테스트로 덮였는지 | 고친 경우에 테스트 없음 | 모두 있음 | 테스트가 없으면 검토가 유일한 그물이다 |

결정: 합계 3 이상이면 다시 받는다. 2 이하면 멈춘다. 다시 받는 데는 사람의 시간이 들지 않으므로 애매하면 다시 받는다. (PR #7은 5회차에도 진짜 결함이 나왔다)

## ② 합치기

AI가 `main`에 합칠지, 사용자에게 물을지 정한다. 합치면 곧 실제 서비스에 배포된다.

반드시 묻기:
- 아래 "반드시 묻는 파일"을 바꾼다
- 경로와 상관없이 로그인·접근 허용·연락처 처리·마이그레이션 적용 방식을 바꾼다(`requireUser`/`requireAdmin`, 연락처 가리기, `LOCAL_PREVIEW`를 더하거나 빼거나 고치는 변경 포함)
- DB의 자료를 지우거나 덮어쓰는 코드를 더하거나 바꾼다, 돈이 드는 새 외부 서비스를 쓴다, 비밀 값이 필요하다
- head 커밋에서 CI 검사 `check`가 성공하지 않았다. 또는 Codex가 끝나지 않았다: `chatgpt-codex-connector[bot]`의 요약 댓글 속 `codex-review-state:v1`의 `code_review`에서 `commit_sha`가 head 커밋이고 `status: completed`, `has_unresolved_findings: false`여야 끝난 것이다. ①에서 멈췄으면 `commit_sha`가 head와 달라 묻게 된다. 정상이다

| 기준 | 2 | 0 |
|---|---|---|
| 바뀐 영역의 위험도 | 외부 입력, AI에 보내는 자료 | 화면 문구, 문서 |
| 테스트로 덮인 정도 | 바뀐 동작에 테스트 없음 | 모두 있음 |
| 합친 뒤 AI가 혼자 확인 | 실제 계정·사이트가 있어야 앎 | Vercel 로그로 앎 |
| 변경의 크기 | 여러 모듈, 수백 줄 | 한 파일, 몇십 줄 |
| 사용자가 보는 동작 | 설계에 없던 방식으로 바뀜 | 그대로이거나 설계대로 |

결정: 반드시 묻기가 없고 합계 3 이하이면 AI가 합친다. 4 이상이면 묻는다. `main`에는 PR 합치기로만 올린다(직접 푸시하지 않는다). 합친 뒤 사용자에게 한두 줄로 알린다: 무엇이 배포됐는지, 계획 문서 주소, 확인할 것.

## ③ 계획 승인

사용자가 승인한 설계 문서에 정해진 것만 따르는 계획은 승인을 기다리지 않고 구현에 들어간다. 사용자는 합친 뒤의 알림(②)으로 계획을 본다.

아래 중 하나라도 해당하면 그 결정만 번호 선택지로 묻는다. 계획 문서 전체를 읽게 하지 않는다.

- 설계에 없던 결정이 있다
- 새 테이블을 만든다
- 새 외부 서비스를 쓴다
- 돈이 드는 일이 생긴다
- 사용자가 보는 동작이 설계와 다르다

## ④ 배포 후 확인

Vercel 프로젝트 `job-hunter`(`prj_JuWhSZfsqdotjWAph0ysJumHWHpP`, 팀 `team_w4vHDxHKH2AsD4651Mq5D220`)에서 AI가 본다. Vercel에서는 배포 상태, 빌드 기록, 오류를 읽기만 한다. 설정, 환경 변수, 배포는 바꾸지 않는다. AI가 합친 변경은 판단 기록에 `→ AI가 합침`으로 적힌 PR이다. 사용자가 합치라고 답한 PR은 사용자가 합친 변경이다.

1. 배포가 끝났는지, 빌드 기록에서 마이그레이션이 적용됐는지 본다
2. `get_runtime_errors`로 오류를 본다. **배포 시각 뒤에 처음 생긴 오류 묶음**만 이 변경의 오류로 본다. 전부터 있던 것은 되돌리지 않고 알린다
3. AI가 합친 변경 때문이면 되돌리는 PR을 열어 바로 합치고 알린다. 되돌리기는 **한 번만** 한다. 되돌린 뒤에도 새 오류가 나거나, 원인이 분명하지 않거나, 사용자가 합친 변경이면 묻는다. Vercel에서 이전 배포로 되돌리지 않는다(`main`과 실제 서비스가 달라진다). 되돌리는 PR은 ②로 채점하지 않는다. head에서 `check` 성공만 보고 합치고, Codex는 기다리지 않는다. 판단 기록에 `되돌리기`로 적는다
4. 오류는 **이름, 횟수, 경로**만 적는다. 로그의 토큰과 사용자 id는 옮기지 않는다
5. 실제 계정, 실제 채용 사이트, 실제 AI의 답의 질이 있어야 확인되는 것만 사용자에게 부탁한다. 무엇을 눌러 보면 되는지 한두 줄로 적는다

## ⑤ 실제 사이트 구조

채용 사이트에 맞춘 수정이 필요하면 먼저 Nimble로 공개 공고 주소를 읽는다. `nimble_extract`에 `driver: "vx8"`, `output_format: "simplified_html"`을 쓴다(2026-11-17 사람인 상세요강 페이지에서 구조가 보였다. 기본 설정은 메뉴만 나왔다). 그래도 본문 구조가 안 보이면 사용자에게 저장한 페이지를 받는다. 로그인이 필요한 페이지는 열지 않는다.

## ⑥ 새 세션

같은 계획 안의 일(구현, 검토 대응, 배포 확인, 그 배포에서 나온 버그 수정)은 한 세션으로 이어 간다. 구현은 작업마다 새 하위 에이전트에 맡긴다(`superpowers:subagent-driven-development`).

다음 때는 사용자에게 새 세션을 권한다. AI는 새 세션을 열 수 없으므로 사용자가 연다. 새 세션은 `docs/status.md`의 다음 할 일부터 한다. 권하기 전에 `docs/status.md`를 고쳐 둔다.

- 지금 계획의 PR이 모두 합쳐지고 배포 확인까지 끝났고, 다음 할 일이 다른 계획 문서(`docs/superpowers/plans/`의 새 파일)다. 이유는 환각이 아니라 집중과 비용이다(긴 대화는 매번 다시 읽힌다)
- 이미 정한 것을 다시 묻는다
- 같은 실수가 되풀이된다
- 문서와 다른 내용을 사실처럼 말한다

## 판단 기록

PR 본문 끝 "판단 기록"에 판단마다 한 줄을 더한다. 따로 기록 파일을 만들지 않는다. 판단표를 바꾼 뒤의 기록에는 `(판단표 YYYY-MM-DD)`를 붙인다.

```
- Codex 재검토 2회차: 심각도 2, 새 코드 1, 추세 2, 영역 2, 테스트 0 = 7 → 다시 받기
- 합치기: 반드시 묻기 없음, 위험 0, 테스트 0, 확인 1, 크기 1, 동작 0 = 2 → AI가 합침
```

## 점검

계획이 하나 끝날 때(`docs/status.md`를 고칠 때) 한다.

- **볼 것**: 지난 점검 뒤 PR들의 판단 기록, 사용자가 바로잡은 일, AI가 합친 뒤 Vercel에 생긴 오류, "멈추기"로 정한 뒤에 나온 결함(놓친 것)
- **직접 만든 장치도 본다**: 아래 표의 장치마다 "없으면 무엇이 깨지나"가 아직 맞는지 따진다. 공식 도구가 같은 일을 하게 됐거나 모델이 좋아져 필요 없어졌으면 지운다. 지우는 것도 점검 결과다
- **적는 곳**: 그 계획 문서 끝의 "판단표 점검"에 판단표마다 맞은 것과 틀린 것
- **고치는 권한**: 더 조심하는 쪽(묻는 조건을 더하거나 다시 받기 쪽으로 기울이기)은 AI가 바로 고친다. 바로 고친다는 것은 그 계획의 PR에 넣는다는 뜻이고, 합치기는 ②를 따른다. 덜 묻는 쪽은 사용자에게 번호 선택지로 묻는다. 고쳤으면 맨 위 "마지막 점검"을 바꾼다
