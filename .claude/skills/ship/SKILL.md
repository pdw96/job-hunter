# 올리기 (검사 → PR → Codex 검토 → 합칠지 묻기)

순서를 건너뛰지 않는다. **사용자가 합치라고 하기 전에는 합치지 않는다**(`main`에 합치면 실제 서비스에 배포된다).

1. **검사**: `npx tsc --noEmit`, `npm run lint`, `npm test`(2분쯤 걸린다). 하나라도 실패하면 고치고 다시 돌린다. 테스트를 건너뛰게 하거나 지워서 통과시키지 않는다
2. **계획 문서**: 구현하다 달라진 점이 있으면 해당 `docs/superpowers/plans/` 문서 끝의 "구현하면서 달라진 점"에 적는다. 계획 하나가 끝났으면 `CLAUDE.md`의 "지금 상태"를 고친다
3. **커밋과 푸시**: 작업 브랜치에 올린다. 비밀 값, `.env*`, 사용자의 개인 자료가 들어가지 않았는지 `git status`로 본다
4. **PR**: 없으면 만든다(초안이 아닌 상태로). 본문은 무엇을 / 왜 / 어떻게 / 확인. 확인하지 못한 것은 그렇다고 적는다. PR 활동을 구독한다
5. **Codex 검토를 기다린다**: PR을 열면 자동으로 시작된다. 결과가 올 때까지 합치기를 묻지 않는다
6. **지적 처리**: 지적마다 코드를 보고 사실인지 확인한다. 맞으면 테스트를 먼저 쓰고 고친다. 해당 스레드에 답하고(끝에 Claude Code 표시를 붙인다) 해결로 표시한다. 고친 내용은 계획 문서에 "(검토)"로 적는다
7. **사용자에게 묻는다**(번호 선택지):
   1. 지금 합치기
   2. Codex 검토를 한 번 더 받기 → PR에 `@codex review`를 남기고 5번으로 돌아간다
8. **합친 뒤**: Vercel의 실제 서비스 배포가 끝났는지 확인한다. 마이그레이션이 있으면 빌드 기록에서 적용됐는지 본다. 작업 브랜치를 `origin/main`에서 다시 시작한다. 사용자에게 실제 주소에서 확인할 것을 한두 줄로 알린다

화면을 바꿨으면 4번 전에 로컬 미리보기로 확인하고 사진을 사용자에게 보낸다(`CLAUDE.md`의 개발 메모).
