# 올리기 (검사 → PR → 검토 → 합치기 → 배포 확인)

순서를 건너뛰지 않는다. 합치기는 `docs/decision-rubrics.md`의 ②를 따른다(`main`에 합치면 실제 서비스에 배포된다).

1. **검사**: `npx tsc --noEmit`, `npm run lint`, `npm test`(2분쯤 걸린다). 실패하면 고치고 다시 돌린다. 테스트를 건너뛰게 하거나 지워서 통과시키지 않는다
2. **계획 문서**: 구현하다 달라진 점을 해당 `docs/superpowers/plans/` 문서 끝 "구현하면서 달라진 점"에 적는다. 계획 하나가 끝났으면 `docs/status.md`를 고치고 판단표를 점검한다
3. **커밋과 푸시**: 비밀 값, `.env*`, 사용자의 개인 자료가 들어가지 않았는지 `git status`로 본다
4. **PR**: 없으면 만든다. 본문은 무엇을 / 왜 / 어떻게 / 확인, 끝에 `판단 기록`(판단표의 "판단 기록"). 확인하지 못한 것은 그렇다고 적는다. PR 활동을 구독하고, 초안이면 풀어서 Codex 검토를 시작한다
5. **검토**: 지적마다 코드를 보고 사실인지 확인한다. 맞으면 테스트를 먼저 쓰고 고친다. 스레드에 답하고(끝에 Claude Code 표시) 해결로 표시한다. 고친 내용은 계획 문서에 "(검토)"로 적는다. 다시 받을지는 판단표 ①로 정해 판단 기록에 적고, 다시 받으면 `@codex review`를 남긴다
6. **합치기**: 판단표 ②로 정한다. 반드시 묻기가 있거나 점수가 높으면 사용자에게 번호 선택지로 묻는다
7. **합친 뒤**: 판단표 ④를 따른다. 작업 브랜치를 `origin/main`에서 다시 시작한다. 계획이 끝났으면 판단표 ⑥대로 새 세션을 권한다

화면을 바꿨으면 4번 전에 로컬 미리보기로 확인하고 사진을 사용자에게 보낸다(`CLAUDE.md`의 개발 메모).
